# Persistent research targets — October 26, 2026

An unrelated Instagram research job redirected the bound TubeLab window after
Threads isolation had already been activated. The installed runtime still had
foreground-window fallbacks in its Instagram, Facebook and Twitter researchers.

Instagram and Facebook now create one independent background window per reader
instance and retain its persistent Safari window ID. Twitter does likewise;
the market-research server no longer passes its UI driver’s ordinal window claim
to this independent reader. Explicit legacy Twitter targets resolve an ID once
and refuse retargeting after binding. Reads and navigation verify platform
origins; a closed target never adopts another foreground document. Temporary
script files are private. No machine-wide browser ownership policy is added.

Real Safari regressions use an actual loopback HTTP document as an independent
witness. Each platform verifies navigation after z-order changes, JavaScript
reads on the bound target, rejection of foreign origins, and closed-target
failure without modifying the witness. TypeScript compilation also passes.
These checks do not prove authentication or successful market-data extraction.

Runtime activation must wait until the existing market-research job is idle.
Preserve its progress and retain old module hashes/backups. Staging source or
compiled files is not evidence that an already-running Node process loaded them.
After activation, verify a fresh TubeLab collection while research operates,
then begin the actual daily-workflow qualification window.
